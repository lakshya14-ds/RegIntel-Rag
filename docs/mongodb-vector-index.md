# MongoDB Atlas Vector Search Index Configuration

This document specifies the schema, configuration, and aggregation pipeline for the MongoDB Atlas Vector Search index used in **REGINTEL RAG**.

---

## 1. Index Definition

- **Index Name**: `vector_index`
- **Collection**: `chunks` (in database `RegIntelCluster` / `regintel`)
- **Embedding Path**: `embedding`
- **Dimensionality**: `768`
- **Similarity Metric**: `cosine`
- **Filter Fields**:
  - `source` (Token / String filter: `"SEBI"`, `"Moneycontrol"`)
  - `category` (Token / String filter: `"Investment Adviser"`, `"Mutual Funds"`, etc.)
  - `document_type` (Token / String filter: `"Circular"`, `"Master Circular"`, etc.)

---

## 2. Atlas Search Index JSON Syntax

Create the vector search index in the MongoDB Atlas Web UI or Atlas Admin API using the following definition:

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 768,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "source"
    },
    {
      "type": "filter",
      "path": "category"
    },
    {
      "type": "filter",
      "path": "document_type"
    }
  ]
}
```

---

## 3. Vector Search Aggregation Pipeline

Vector retrieval queries are executed using MongoDB's `$vectorSearch` stage at the start of the aggregation pipeline:

```python
pipeline = [
    {
        "$vectorSearch": {
            "index": "vector_index",
            "path": "embedding",
            "queryVector": query_vector,  # 768-dim normalized float list
            "numCandidates": 100,
            "limit": 5,
            # Optional metadata filter:
            # "filter": {"category": {"$eq": "Investment Adviser"}}
        }
    },
    {
        "$project": {
            "_id": 0,
            "chunk_id": 1,
            "document_id": 1,
            "title": 1,
            "content": 1,
            "section": 1,
            "source": 1,
            "category": 1,
            "document_type": 1,
            "published_date": 1,
            "effective_date": 1,
            "url": 1,
            "score": {
                "$meta": "vectorSearchScore"
            }
        }
    }
]
```

---

## 4. Key Attributes

1. **Cosine Similarity**: Embeddings generated by `gemini-embedding-001` with dimensionality `768` are L2-normalized upon creation, ensuring cosine similarity ranges reliably between `-1.0` and `1.0` (mapped to `0.0` - `1.0` in `$meta: "vectorSearchScore"`).
2. **Deterministic IDs**: Every chunk has a deterministic unique ID (`<document_id>_chunk_<index>`) to ensure exact deduplication and reference integrity.
3. **Embeddings Omission**: Retained document projections deliberately omit the 768-dimensional `embedding` array from query outputs to conserve memory and bandwidth for LLM prompt context construction.
